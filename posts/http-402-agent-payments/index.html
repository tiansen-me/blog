0.005 美元与 29 年：HTTP 402 终于等到了不会注册的客户端

tian.sen 发表于 11-162026-11-16T20:03:17+08:00
25 分钟 阅读

一条带着价签的 402

2026 年 11 月 16 日晚上 8 点 02 分，我在终端里敲了这么一行：

1

curl -i 'https://search.agent.s.brave.app/res/v1/web/search?q=rust'

这是 Brave 搜索 API 一个新上线的付费端点。我没带任何凭证——没有 API key，没有登录态，什么都没有。回来的响应是：

把那串 base64 解开，是一个结构化 JSON：服务名“Brave Search”，商品描述“Web search over Brave’s independent index”，然后是关键的一段——

"accepts": [{
  "scheme": "exact",
  "network": "eip155:8453",
  "amount": "5000",

  "payTo": "0xFFa76529d7e733C7671190b374819d8eDA2b9D04",
  "maxTimeoutSeconds": 300,
  "extra": { "assetTransferMethod": "eip3009", "name": "USD Coin", "version": "2" }
}]

翻译成人话：这条搜索，0.005 美元（USDC 有六位小数，5000 个基本单位就是半美分），收 Base 链上的 USDC，收款地址明码写着，授权签好后 300 秒内有效。响应头就是一张价签，一个会读 JSON 的客户端拿到它，就知道接下来该干什么、该付多少、付给谁。

这就是 x402 协议在工作。HTTP 402 这个状态码在规范里躺了将近 29 年，从 1997 年的 RFC 2068 起就标注着“Payment Required”，但几乎没有任何服务器真的返回过它。2026 年 11 月 12 日，Brave 宣布搜索 API 接入 x402，按次收费、无需账户、无需 API key——而就在前一天，这个故事的另一半写进了联合航空的合同条款里。

我想讲的就是这两半。

一个状态码为什么能睡 29 年

先补协议史。402 是 HTTP/1.1 的第一批状态码之一，RFC 2068（1997 年 1 月）定义，备注“reserved for future use”。同期 Web 世界其实认真研究过微支付：上世纪 90 年代末 W3C 攒过一个微支付工作组，无疾而终；2010 年代又冒出一批基于比特币的微支付创业公司，也没能活过冬天。HN 用户 com2kid 在讨论里说得更直接：Visa 在 1999 年技术上就能做微支付，是广告模式赢了（社区观点，但它点中了要害）。

回头看，微支付反复失败的原因，从来不是结算成本，而是身份。传统支付管道的每一环都默认另一头是个人：注册要邮箱，绑卡要持卡人姓名，风控要人脸，退款要走持卡人申诉。每一次“付一毛钱读一篇文章”的尝试，最后都死在“为了付一毛钱，你得先完成 30 块钱的身份流程”上。

x402 把这件事讲透了。它是 Coinbase 2025 年 5 月发布的规范，2026 年 4 月交给 Linux 基金会，7 月 14 日 x402 基金会正式运作时，创始成员里站着 Adyen、AWS、美国运通、Circle、Cloudflare、Google、Mastercard、Shopify、Stripe、Visa——17 家“高级成员”，几乎把现有支付产业的一半都装了进来。一份由竞争死对头共同署名的开放协议，这件事本身比任何一家采用它的 API 都更值得注意。

真正让 402 醒过来的技术细节是 EIP-3009。我解出来的那段 accepts 里，assetTransferMethod: "eip3009" 意思是：客户端要对 USDC 合约签一个“转账授权”（transferWithAuthorization），而不是发起一笔链上交易。签名本身不花 gas，也不需要客户端持有以太坊用来付手续费；真正把交易提交上链、垫付 gas 的是 facilitator——在 Brave 这个案例里，facilitator 是 Brave 自己运营的，Brave 同时宣布限时内替你承担 Base 链的 gas 费。于是一次 0.005 美元的付款，对客户端来说只是一次签名加一次重试，全程没有“账户”这个概念参与。

一个状态码睡了 29 年，不是在等更好的支付技术。它等的是一个不会注册、不会绑卡、也不会数钱的客户端。现在这个客户端出现了。

签名就是钥匙：支付如何取代账户

把 Brave 这个案例拆开看，它的激进程度容易被“支持加密货币支付”这个说法低估。真正的变化是：凭证的形态换了。

用传统方式接一个搜索 API，流程是：注册账户、选套餐、填信用卡、生成 API key、把 key 配进环境变量、定期轮换。这六步里没有一步是 Agent 自己能完成的，每一步都预设了一个人在浏览器里操作。而接入 x402 之后的流程是：给 Agent 的钱包充一点 USDC，完事。Brave 的原话是“a Brave Search API account is no longer needed”——签名本身就是凭证，钱包余额就是套餐。

更值得看的是 Brave 为此写的那份 llms.txt。它开门见山：“A pay-per-request proxy in front of the Brave Search API. Each request carries a stablecoin micropayment, and the signed payment is the credential.” 然后用一张表列出所有在售路径和价格——八条路径，全部 5000 基本单位。文件末尾还有一句在我看来是整个设计里最像“协议哲学”的话：“the 402 response from a paid path is the authoritative statement of what that exact request costs”——一切以 402 响应里的实时报价为准，价目表仅供参考。

这个细节马上就被现实兑现了。Brave 官方文档里的示例命令写的是 --max-amount 10000（0.01 美元），而公告和 llms.txt 里的价格是 5000（0.005 美元）。照抄示例的人会授权双倍的钱。这种文档打架在任何 API 都是事故，但在 x402 里却有个原则性的答案：不背价目表，读 402。价格为谁、何时、多少，由服务端在那一刻说了算，客户端每次现读现付。对 Agent 来说这反而是最舒服的模式——它本来就不该记忆价格，只该带着预算去读价签。

顺带一提给这个模式上了双保险的细节：llms.txt 明确写“a payment is checked against the price of the path it is sent to, so a payer cannot name its own price”——付款金额会被核对到该路径的定价，Agent 不能自己开价。配合 300 秒的授权有效期，一次握手在协议层上已经把“读了假价签”“签了过期单”“付错金额”这几种最常见的坑都堵上了。

还有个小讽刺值得记下来。Brave 推荐的命令行钱包叫 Purl，是 Stripe 开发的；而 Stripe 自己另有一套并行标准 MPP（Machine Payments Protocol），同样基于 402 状态码。我解码的那份 402 响应体里，extensions 字段下同时挂着 mppx 和 x402 的 bazaar 信息——同一张价签，两个协议都能读。两条路线从竞争走向在同一个响应头里共存，这大概是“支付协议也终于学会不锁死客户”的最好注脚。

0.005 美元下面的地板

这份 llms.txt 里最有意思的部分，是它没卖什么。

Answers API（/res/v1/chat/completions）不卖，理由是它“按查询加按 token”双重计费，一个固定价格表达不了。Autosuggest 和 Spellcheck 不卖，理由更直白：它们的单价低于 facilitator 结算一笔支付收的手续费，“等以后把很多次查询打包成一笔支付再卖”。Summarizer 不卖，因为整个功能已弃用。

这三条排除项放在一起，把 x402 当前的能力边界写得清清楚楚：

第一，它只会说“一口价”。 x402 的 exact 方案是按次定价，表达不了计量计费。搜索天然是“一次请求一个价”的商品，所以它是 x402 最顺滑的载体；但现实的 API 世界里大量服务是阶梯、计量、订阅混合计费，那些要么继续留在 API key 体系里，要么等协议长出更复杂的报价能力。

第二，它有地板。 单次结算是有成本的——行业里的参照是 Coinbase CDP 的 facilitator：每月前一千笔免费，之后每笔 0.001 美元。Brave 把价格定在 0.005 美元，刚好是那道地板的五倍，安全；而 Autosuggest 这种千分之一美元级的商品，会被结算成本吃掉全部毛利。微支付协议的“微”，也是有限度的“微”。llms.txt 里那句“等打包结算”，其实已经预告了协议下一步要长出的东西：批量授权、账期、垫付——换句话说，信用卡体系用二十年建好的那套东西，链上得一样一样重新发明。

同样的地板也解释了为什么第一个跑通的不是“付费读一篇文章”（这是 90 年代微支付的执念），而是搜索：0.005 美元的商品足够便宜，Agent 值得“顺手买一个”；又足够贵，高于结算地板。Web 内容如果哪天走这条路，定价得先过这道算术题。

墙与门：同一个问题，两种答案

现在说另一半。就在 Brave 挂出价签的前一天——2026 年 11 月 11 日——联合航空修订了运输合同，新增规则 6.J.6：禁止使用 AI Agent 订票、改票、值机或购买任何相关产品。注意三点：第一，禁令覆盖“AI 助手、独立 Agent、带 AI 的浏览器”，甚至包括 Agent 通过 Expedia 这类在线旅行平台间接触达；第二，即便乘客全程监督并批准了 Agent 的每一步操作，也算违规；第三，配套的 5.H 规则给了联合航空不事先通知就取消这类订单的权利。这是美国主要航司里第一家把禁令写进合同条款的。达美上个月就被报道在封堵类似的工具。CEO Scott Kirby 在芝加哥一场活动上把真实动机说了出来：“说实话，我不想再造一个中间商。”

同一周，Agent 伸手去够 Web 服务，得到了两个截然相反的回应：联合航空在门口挂上“禁止入内”，Brave 在门口装了门铃和价签。

这两个动作看着对立，其实在回答同一个问题：当客户端不再是一个会注册、会签合同、会承担责任的“人”时，你的入口拿什么接待它？

联合航空的答案是不能接待。它列的理由有相当部分是成立的：值机时旅客要依法确认行李中无危险品（49 CFR 175.25），这个确认动作现在只能由人完成；Agent 买错日期、误读票价规则的损失由谁兜底，现有的分销体系里没有对应的责任主体。但它答不出的是另一个问题：既然 Agent 迟早会来，“禁止入内”和“请走人工通道”的合同条款，对一个技术上无法与普通 OTA 订单区分的请求，究竟拦得住谁？一个在 Expedia 平台内完成下单的 Agent，联合航空的订单系统里看到的只是一笔普通的 Expedia 交易。合同禁令是谈判工具，不是技术边界。

Brave 的答案是可以接待，但明码标价、先付后用。搜索恰好是那个最适合装门铃的场景：单次请求独立可验证、结果质量用户当场能感知、买错了损失也就半美分。0.005 美元既是价格，也是准入政策——你不需要注册，不需要商务谈判，不需要 KYC，钱包里有钱就能进。这恰恰是联合航空最头疼而搜索 API 无所谓的差异：出错的代价函数完全不同。一张机票几百美元、一次值机错误不可逆；一次搜索半美分、买了不满意拉倒。x402 的门铃能装在搜索上，不是因为协议高明，是因为这门后没有值钱到需要审查每一个进门者的东西。

所以把这两个动作放在一起读，正确的结论不是“Brave 进步、联合航空反动”，而是：Agent 经济的准入，最终会沿着“损失函数”分层展开。损失半美分的场景用价格做准入（402），损失几百美元的场景要么长出可问责的授权结构（商业账户、保证金、保险），要么继续把门焊死。联合航空说自己在等“标准化且安全的集成方式”，这话未必是托词——它等的其实是责任主体，而 Brave 已经用钱包余额把责任问题简化成了“余额不足”。

还没有人真的在付钱

写到这里，必须把冷水也端上来。

HN 那条讨论（两百余赞、百余评论）里怀疑声不算小。最扎的一条来自用户 ddxv：他给一个被大量爬取的站点接了 x402，至今零交易。Reddit 上也是类似调子——他自己总结：“现在往 x402 里充钱的，都是想验证 x402 能不能用的人。”这是单一用户的经验，无法证伪 Brave 端的真实流量（Brave 没公布任何交易量数字），但它指出了这个叙事目前最大的空洞：协议、基金会、价目表都齐了，独独缺真实付款的实证。

比流量更结构性的问题是安全模型的转移。API key 泄露，最坏结果是数据和额度被盗刷，你可以找服务商封禁；而 Agent 钱包的私钥泄露，丢的是钱本身，是链上资产，追不回。HN 用户 brodydung 把更实际的缺口也点了出来：支付通道根本不是瓶颈，瓶颈在支付之前——Agent 不会只搜一次，同一个问题换个措辞重搜就是一次新的扣费，缺的是每任务预算上限、近似查询去重、可审计的账单。这跟我在《187 封邮件与 0 元退款》里写过的停止条件是同一个问题换了张脸：一个只会付款、不会看余额的 Agent，和一个只会发邮件、不会收手的 Agent，是同一种工程缺陷。钱包把“额度管理”从服务商的套餐系统挪到了客户端，就等于把停止条件的编写责任也一并挪给了客户端。

所以我的判断是：x402 这一层的协议设计，已经交卷了，而且答得比我预期的好——身份问题被签名消解、报价问题被 402 消解、gas 问题被 EIP-3009 消解，连协议分叉都被 extensions 字段消解了。但协议下面的配套还欠三样东西：预算封顶（不该是 --max-amount 这种一次性参数，该是每任务策略）、托管钱包（私钥不该躺在 Agent 的环境变量里）、争议处理（chargeback 在这个世界没有对应物，退款与否目前全靠厂商自觉——同样接了 x402 的搜索同行 Tavily，做法是上游调用失败后自动把 USDC 退回签名钱包）。这三样不到齐，x402 就只是给测试者准备的玩具。

结语

微支付死过很多次，每次验尸报告的死因都写着同一句话：客户端背后有个人，而人不会为了半美分走完身份流程。29 年后，402 等到的不是更便宜的结算，也不是更快的链——是终于出现了一种客户端，它没有身份可以证明，也不在乎花掉的每一分钱，它只读价签。

联合航空和 Brave 这周一起告诉了我们接下来的格局：损失小的地方，门会自动打开，价签就是门禁；损失大的地方，门会先焊死，直到有人发明出让 Agent 能被问责的办法。前者已经发生了，后者才是未来两年真正的战场。

至于那 0.005 美元的搜索到底有没有人真的在买——我建议年底再去看一次那些在 HN 和 Reddit 上发牢骚的站长。到时候他们的交易记录，比任何白皮书都诚实。
