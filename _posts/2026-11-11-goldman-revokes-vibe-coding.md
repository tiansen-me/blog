## 7 月的鼓掌，10 月的通知

2026 年 7 月，高盛首席信息官 Marco Argenti 还在公开场合为一个潮流站台。他说的场景很具体：交易员和银行家用 Claude Code 写出工具的第一版，再交给行里约 1.2 万名工程师打磨成生产级软件。他给这种工作流起了个当时正热的名字——vibe coding：你只描述想要什么，代码让 AI 去写，你甚至不必看它写了什么。

三个月后，内部指导意见悄悄更新：Claude Code 和 GitHub 的编码工具，只留给工程师，以及高盛内部横跨交易、量化和软件工程的"strats"。交易员和银行家——这几个月里真的在用这些工具追踪客户交易流、模拟市场和头寸变化、起草文字和配图材料的人——被关在了门外。据 Bloomberg 2026 年 11 月 2 日的报道，一些交易员对此相当不情愿。

11 月 8 日，State of AI 的一篇复盘把这个内部政策顶上了 Hacker News 首页，当晚就冲到 700 多分、近 400 条评论，并在首页停留数日。一家公司的一条内部权限政策，能在外部技术社区炸出这么大声量，说明大家意识到这不是高盛的家务事。

我的看法一句话就能说完：**这不是一次「AI 退潮」，而是第一家大机构给代码 Agent 划出的身份线——会写代码的 Agent 是开发者工具，得按开发者的规矩用，而不是按生产力玩具用。** 而这条线划在哪，比大多数人以为的更精确。

---

## 一、四个月里到底发生了什么

把时间线拉直了看，高盛的动作其实是一组方向一致的拧紧：

- **2026 年 4 月**，高盛把 Claude 从香港银行家的内部平台下架。据路透社当时转述《金融时报》的报道，理由是对与 Anthropic 合同条款的严格解读——Anthropic 的说法是 Claude 从未在香港正式提供服务。
- **2026 年 7 月**，CIO Argenti 公开赞扬非技术员工用 AI 造工具、工程师接手优化的模式。
- **2026 年 10 月**，内部指导意见更新：Claude Code 与 GitHub 编码工具限工程师和 strats 使用。
- **2026 年 11 月 2 日**，Bloomberg 报道此事；发言人 Nick Carcaterra 的回应值得逐字读——

> 我们让员工使用某些 AI 工具，是为了在全行不同部门找到最佳用例。在一段评估生产力与风险管理等多种因素的试验期之后，我们会把它们交到最适合长期使用它们的人手里。

注意这段话的结构：试验、评估、收回——是一个完整的治理动词序列，而不是一次事故驱动的紧急刹车。截至发稿，没有任何报道提到高盛因为某次具体事件而收回工具。

还有一个常被略过的细节：**高盛自己开发的多模型 AI 助手（接 OpenAI、Anthropic、Alphabet 的模型）仍然对全员开放。** 被收走的只是「会写并执行代码的第三方 Agent」这一类工具。

所以第一个结论是：高盛收回的不是 AI，甚至不是 Claude——它收回的是「谁能在这台机器上生产并运行代码」的许可。聊天、总结、写邮件草稿，照旧；代码，不行。

## 二、代码审查不是过滤器，是问责制度

vibe coding 这个词的原始含义就带着一点挑衅：Karpathy 造这个词时说的就是「忘记代码的存在，交给 AI」。这套叙事在 2026 年被讲成了企业故事：非技术员工点子多、懂业务、等不起工程师排期，让 AI 替他们把点子变成工具，工程师负责收尾。

高盛用四个月验证了这个故事里最薄弱的一环：**收尾环节不会发生。**

HN 讨论里，一位自述在类似机构维护业务部门自制工具的工程师（用户 cloudednine）对着 Argenti 7 月的说法回了一句：“我总觉得‘工程师负责改进’这句里的‘改进’承担了太多它扛不动的东西。”这条评论的语境是：一个交易员用 AI 生成的、每天早上跑一遍的客户流水监控脚本，本质上是生产系统——它没有经过代码评审，没有单元测试，没有合规校验，没有一个具名的负责人。当它出错时，审计记录里查不到任何人的名字。

这就是我想展开的第一条论证线：**代码审查的真正功能不是抓 bug，是建立问责。** 银行是地球上对「这段代码是谁写的、谁批准的、以谁的名义运行」要求最严的行业——投行部做一单 IPO 的银行家和交易自家账户的交易员之间必须隔着信息墙（information barrier），这是证券法层面的合规义务，不是最佳实践。一个能读本地文件、能联网、以操作者身份执行命令的 Agent，恰好可以成为穿透这堵墙的通道：银行家把自己桌上的信息喂给工具，工具的上下文流向交易台正在用的同一套系统。

HN 最高赞评论（用户 lukebuehler，楼下一百多条回复）把这个风险归入了 Simon Willison 提出的「致命三要素」：能接触私密数据、能看到不可信内容、能把数据送出去。三者凑齐，Agent 在哪台机器上都是危险品，而交易员的工作站三样全占。

当然，反方声音也在。同帖里有人（用户 jeremyjh）认为桌面是高盛自管的，沙箱化或远程托管就能控制风险，真正的危险是「作者自己都不理解的坏代码引发错误交易」；还有人翻出那句老实话：银行十几年来一直在跑「几千个带神秘宏的 Excel」，凭什么 vibe coding 更危险？这是社区观点，我原样转述。但我的回答是：**Excel 宏的爆炸半径是一张表；一个以你身份运行、能摸到文件系统和内网的 Agent，爆炸半径是整台机器和它背后的一切。** 这是量级之差，不是性质之差。

## 三、按角色授权，不按工具授权

第二条论证线藏在这条政策最容易被误读的地方。

很多转述把这件事讲成「高盛禁用了 Claude Code」。但请注意：**高盛的 1.2 万名工程师继续用它。** 工具本身没有任何问题，出了问题的从来不是模型，是坐在工具前面的那个人有没有配套的管道——评审、测试、变更管理、审计。工程师有这条管道，交易员没有。所以授权跟着角色走，而不是跟着工具走。

这条分界线的精确之处在于它划定的分类学：

| 类别 | 例子 | 在高盛的待遇 |
|---|---|---|
| 助手（对话、生成、不执行） | 自研多模型 AI 助手 | 全员可用 |
| 代码 Agent（写并自主执行代码） | Claude Code、GitHub Copilot | 仅工程师与 strats |

对做企业内部工具的人来说，这张表可以直接抄。它的潜台词是：**信任的基本单位不是模型，是席位（seat）**——同一个模型，放在工程师的终端里和放在交易员的桌面里，是两种风险等级完全不同的东西。

还有一个大家都津津乐道的「讽刺」必须说清楚：高盛（与摩根士丹利）正是 Anthropic 上市的主承销商——它一边在资本市场推销这家公司的股票，一边把这家公司的旗舰编码工具从绝大多数员工手里收走。HN 上有人觉得时机微妙。但另一位用户（pdpi）的反驳更接近大机构的真实运作：在治理正常的公司里，做风控决策的人和做承销业务的人「不互相汇报、也不应该互相汇报」；如果真发现了安全风险，等几周再处理才是失职。而且从商业上说，这笔账算得过来：一家银行能同时做到「承销 Anthropic」和「管住 Anthropic 的工具」，恰恰是向所有受监管客户发出的最硬的背书——**买这家公司的股票，和管好这家公司的产品，不冲突。**

顺带一提成本这条暗线。HN 里一位用户（legitster）自述其雇主正在因为「长期账单超标」往回收 Claude 的使用权限——这只是某一家公司的个案，且高盛官方口径里提到的因素是生产力和风险，不是钱。但按 token 计费的 Agent 铺给几万名非工程师，费用曲线是什么形状，做过企业预算的人都能想象。

## 四、这份答卷对你有什么用

高盛不是唯一在收线的银行——据行业转述，同期摩根大通与嘉信理财已禁止外部 Agent 访问客户账户，巴克莱则在用编码 Agent 缩减工程师编制。方向相反，逻辑相同：都在回答「谁可以在什么数据上运行代码」。

对任何一家正在给员工铺 Agent 的公司，高盛用四个月试验期换来的东西，可以浓缩成三个在发权限之前就必须有答案的问题：

1. **这段代码出事时，审计记录里写谁的名字？** 答不出「谁负责」，就不该让它跑在真实数据上。
2. **它以谁的身份运行，能摸到什么？** Agent 继承的是操作者的权限和上下文——给交易员发 Agent，等于给交易员的数据访问权限再开一个不受审计的副本。
3. **它进不进得去不该进的通道？** 信息墙、数据权限、外发通道，这些边界要在 Agent 的权限设计里显式存在，而不是寄希望于模型「有分寸」。

HN 社区里流行一种略带幸灾乐祸的论调，有人说这是「第一次见到如此清晰的技术先行者劣势——像一战堑壕，第一批冲上去的人被撕碎，最好坐着看」。我不这么认为。高盛花四个月买到的这个分类学——助手归全员、代码 Agent 归工程、授权跟着角色走——比任何咨询报告都便宜。**先行者被撕碎的前提是学费白交了；高盛的学费没白交，它把答案公开了。** 真正该担心的不是试错的机构，是那些把 Agent 铺给全员、却还没问过上面三个问题的机构——他们现在连「自家有多少 vibe 出来的脚本在跑」都数不出来。

## 结语

vibe coding 的字面意思就是「放弃理解」。它作为个人学习方式无可厚非，但放进组织里，「放弃理解」的代价从来不由写代码的人承担，而是由数据的主人、风控的负责人和下一个接手的人承担。

高盛四个月的试验证明了一件事：在受监管的行业里，代码是一种制品（artifact），制品必须有主人。模型能力再涨，也替代不了「这段代码是谁的」这个问题的答案——因为监管问的从来就是这个，而不是「这段代码写得好不好」。

1.2 万名工程师留下了，其他大多数人回到了自研助手面前。这条线以后会被反复引用——它是第一块被官方竖起来的界碑，而界碑这种东西，一旦立下，很少会被推倒。
